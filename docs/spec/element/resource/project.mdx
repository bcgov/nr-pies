A project serves as a grouping of related assets within the PIES system.

## Scope

This resource type is transmitted within a [Record](/docs/spec/element/message/record) message by setting `asset_kind`
to `PROJECT`. It is designed to describe the properties of the grouping of related assets within the PIES system. This
is typically framed from the perspective of the system that is declaring the asset, and may not reflect the perspective
of other systems.

Refer to [Record](/docs/spec/element/message/record) for details on the message envelope pattern and how resource types
are selected.

## Structure

This structure contains no properties and is functionally equivalent to an empty object.

:::info
A **Project** extends the following data types and inherits all of their declared attributes:

- **[Collection](/docs/spec/element/data/collection)**

The table below identifies the inherited data types (in parentheses) and lists the properties declared directly by
Project.
:::

| Name           | Cardinality | Type                                             | Description & Constraints                                                                                                |
| -------------- | ----------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| _(Collection)_ | 1..1        | [Collection](/docs/spec/element/data/collection) | A collection serves as a common construct for describing resource data elements that group other data elements together. |

## Implementation Guidance

The Project resource type is an empty object and does not define any properties. Systems parsing projects should
ignore any unexpected properties.
